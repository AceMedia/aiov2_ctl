### Rail Boot Service (installed automatically)

`--install` also installs and enables a systemd oneshot unit:

- `aiov2-rails-boot.service`
- Unit path: `/etc/systemd/system/aiov2-rails-boot.service`
- Purpose: apply configured GPIO rail boot states at startup via:
  - `aiov2_ctl --apply-boot-rails`

Verify after install:

```bash
systemctl is-enabled aiov2-rails-boot.service
systemctl status aiov2-rails-boot.service --no-pager
aiov2_ctl --boot-rails-status
```
```

## Rail Boot State Commands

Set per-feature rail state to apply at system boot:

```bash
aiov2_ctl --boot-rail <FEATURE> on
aiov2_ctl --boot-rail <FEATURE> off
aiov2_ctl --boot-rail <FEATURE> status
aiov2_ctl --boot-rails-status
```

Supported features:

- `GPS`
- `LORA`
- `SDR`
- `USB`

Examples:

```bash
aiov2_ctl --boot-rail SDR on
aiov2_ctl --boot-rail LORA off
aiov2_ctl --boot-rail SDR status
aiov2_ctl --boot-rails-status
```

Notes:

- `on/off` updates effective boot configuration used by the boot service.
- Settings are applied at startup by `aiov2-rails-boot.service`.
```

### Rails on boot submenu

The right-click menu includes a **Rails on boot** submenu for per-feature boot preferences.

Important distinction:

- Main feature toggles = **live rail state now**
- **Rails on boot** toggles = **persisted boot preference**

So a feature may be OFF in the main live toggle while still set ON in boot preference (or vice versa), depending on current runtime state.

## GPIO State Interpretation

GPIO on/off state is interpreted in this order:

1. `hi` => ON (`pinctrl` source)
2. `lo` => OFF (`pinctrl` source)
3. `--` (not driven) => per-pin boot fallback (`boot_default` source)

This keeps runtime state truth-first and only uses boot fallback when the pin is not actively driven.

### Debug source labels

To show source labels in status output:

```bash
AIOV2_CTL_DEBUG=1 aiov2_ctl --status
```

Source labels:

- `(pinctrl)` from explicit `hi/lo`
- `(boot_default)` from `--` fallback
- `(unknown)` unparseable/failed read path
```

## Boot preference set but live rail OFF

If a feature is configured ON at boot but appears OFF live, check the boot apply path end-to-end.

### 1) Check configured boot preferences

```bash
aiov2_ctl --boot-rails-status
```

### 2) Check boot service state

```bash
systemctl status aiov2-rails-boot.service --no-pager
systemctl is-enabled aiov2-rails-boot.service
```

### 3) Check boot service logs for current boot

```bash
journalctl -u aiov2-rails-boot.service -b --no-pager
```

### 4) Check raw pin state and interpreted status

```bash
pinctrl get <pin>
AIOV2_CTL_DEBUG=1 aiov2_ctl --status
```

Interpretation:

- `hi/lo` should report source `(pinctrl)`
- `--` should report source `(boot_default)`

If needed, apply configured boot states immediately (without reboot):

```bash
sudo aiov2_ctl --apply-boot-rails
```
```
